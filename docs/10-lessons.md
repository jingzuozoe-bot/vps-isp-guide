# 从失败里留下可复用的教训

这里是脱敏案例，不包含私人设备、地址、凭据或原始日志；也不把历史单次结果当作本库认证。

| 发生过的情况 | 教训 | 新用户应该怎么做 |
|---|---|---|
| SSH 活着，上游拒绝代理请求 | 传输存活不代表服务可用 | VPS→ISP 独立验证 |
| 白名单认证没有密码，被误判缺配置 | 认证模式不同 | 白名单模式可无凭据，别硬塞空密码 |
| 管理进程读不到用户私密文件 | 管理权限与隐私权限不同 | 普通用户准备候选，管理员只做必要系统变更 |
| 规则预检文本与加载后显示不同 | 全文相等不能当然证明规则身份 | 需要经验证的语义核对；不忽略未知规则 |
| 恢复先检查规则，出错后不解除应用锁 | 恢复依赖防护自身会形成死锁 | 独立解除路径，先验异常恢复 |
| 应用目录 ACL 重启后仍保留 | 权限锁是持久状态 | 本库不推荐用目录锁作入门防护 |
| 回退返回码 0，正文或真实连接失败 | “成功”可能只是一层退出成功 | 核返回码、正文、实际网络三者 |
| 服务器与电脑新入口请求通过，手机导入后完全断网 | 服务端成功不能代替手机实测，节点导入与规则/DNS 接管须分别核对 | 手机方案仍为失败/待审计，不能交付为可用教程 |
| 手机本机锁屏通过，热点电脑仍断网 | 本机与共享网络不同 | 分设备、分场景测试 |
| 恢复后 IP 正确，被当成故障窗口安全 | 恢复证据不覆盖故障期 | 记录请求时间和故障窗口 |
| UDP/WebRTC 单页未见泄漏 | 一个网页不是全协议测试 | DNS/IPv6/UDP/应用单独验收 |

设计原则：先做普通代理的局部验证；严格停连作为独立工程，不能靠更多开关、应用锁和“自动恢复”文案来宣布完成。
