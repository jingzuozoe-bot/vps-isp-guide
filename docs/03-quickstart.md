# 从零开工：每次只推进一个检查点

目标：让你保留原网络与恢复能力，再逐段建立 VPS→ISP。

## 0. 告诉 Agent 最少的信息

电脑/手机是什么系统？有没有 VPS、ISP、客户端？现在靠哪个网络聊天？是否必须故障停连？不要贴密码、真实订阅或订单截图。Agent 可读本地信息时先自行盘点，再问缺项。

使用 [盘点模板](../templates/inventory.md)，记录版本、原代理/DNS、已有 VPN、远程联络依赖、业务不能中断的范围。输出只需脱敏摘要。

## 1. 没买的才买

按 [采购指南](02-buying.md) 填订单摘要。地区、最终价格、退款和续费未明就先核，不由 Agent 自动付款。已有套餐优先复用，别为了跟教程一致重买。

## 2. 保存离线恢复卡

填写 [恢复卡](../templates/recovery-card.md)，保存到本地且能离线打开。切网前明确原网络如何回来，手机或另一条链路能否联系。不要把旧代理自动塞进新代理 fallback。

## 3. 先跑电脑的局部 TCP 路线

阅读 [SSH 参考路线](04-reference-route.md)。先验证 VPS 到 ISP，再验证本地显式代理请求；此时不切系统代理、不动 DNS、不启 TUN、不启常驻服务。

参考路线适合能用 OpenSSH 的 macOS/Linux。Windows 需确认 OpenSSH 和命令环境；手机必须用独立适配，不把电脑 localhost 写进手机。

## 4. 再接入一个客户端或应用

先导入独立候选配置，保留旧配置。语法验证成功后，只让一个测试应用显式使用新入口。应用是否接受代理以其当前官方说明和真实请求为准。不要把终端代理环境变量通过视为桌面应用已接入。

## 5. 验收并交接

按 [检查点](06-checkpoints.md) 逐项记录。需要全机故障停连，而现有软件做不到时，停止在普通模式，不把勾选开关写成保证。

收尾发给用户：现在用什么、通过什么、未测什么、怎样恢复、下次从哪里继续。填 [交接模板](../templates/handoff.md)。

本库不会为了“无痛”隐藏系统权限或假装一键解决所有平台；Agent 应承担查文档、生成候选、核验和交接的工作。
