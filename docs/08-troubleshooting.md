# 按层排查，别同时改五个开关

| 现象 | 先查 | 下一步 |
|---|---|---|
| SSH 进不去 | VPS 状态、SSH 端口、指纹、密钥、供应商控制台 | 保留现有会话，不关闭身份检查 |
| SSH 已连接但代理失败 | VPS 到 ISP 的单独请求 | 查订单、白名单、端口、认证 |
| 407/认证失败 | 协议、完整凭据、源 IP 白名单 | 无密码白名单模式合法；半套凭据不合法 |
| 本地端口占用 | 是否已有隧道/其他客户端使用 | 换候选端口，不杀不明进程 |
| 出口是 VPS | 是否误用 ssh -D 或存在直出节点 | 应使用指向 ISP 端点的 -L 或正确链式出站 |
| 出口是本地 | 应用是否遵守代理、是否有绕过规则 | 单应用接入另验，停止敏感操作 |
| 网页好、应用坏 | 应用代理支持、上传/长连接、DNS | 查该应用官方配置，不凭 IP 页判已通过 |
| 只有部分网站慢 | VPS→ISP 质量、上游公平使用限速 | 分时比较完整链路，不先买更大内存 |
| DNS 显示 Cloudflare 等 | 与远端解析对照、客户端 DNS 路径 | 不只凭公司名判断泄漏 |
| 手机可用，热点电脑断网 | 锁屏、省电、VPN 网络接管组合 | 手机/热点分开留证，保留电脑独立网络 |
| 手机导入 localhost 后失败 | localhost 是手机自身 | 重新设计手机加密入口，不开放电脑无认证代理 |
| 重启后应用打不开 | 是否遗留权限/ACL/安全软件动作 | 按已登记变更精确撤销，不叠新锁 |
| 日志写成功但网络没恢复 | 正文错误、实际服务状态和真实请求 | 返回码不能单独证明恢复 |

一次只改一个变量，记录改前、改后与回退。错误日志先脱敏；`-v`/抓包可能包含认证信息，不直接贴 Issue。

求助时使用 [问题模板](../.github/ISSUE_TEMPLATE/problem.md)，只发版本、阶段、时间、脱敏错误和已做恢复。不要发订单、真实 IP、配置全文或订阅 URL。
