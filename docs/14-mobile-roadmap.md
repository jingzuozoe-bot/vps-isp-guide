# 手机怎么走：先明确入口，再导入和验收

目的：给手机一条从架构到测试的路线，同时避免拿电脑结果充当手机成功。

## 两种路线不能混用

电脑可以用本机 OpenSSH；手机通常需要兼容的加密客户端协议。手机的参考架构是：

```text
手机客户端 → 加密协议入口 → VPS 上独立代理进程 → ISP SOCKS5/HTTP → 目标网站
```

客户端必须支持所选加密协议，服务器进程必须明确以 ISP 为出站。直连 ISP 代理不等于经 VPS；只导入 VPS 节点也不等于已加 ISP 最后一跳。

## Agent 的适配顺序

1. 确认手机 OS、客户端精确版本、现有可用配置和恢复按钮。保留电脑独立联络，不删旧节点。
2. 按客户端与服务端当前官方文档选择兼容协议；密码、证书、算法和协议版本明确对应，不靠换端口假装增加加密层。
3. VPS 使用独立候选目录、账号和端口，不复用未知服务权限；新增公网监听前写明认证、暴露范围和撤销办法。
4. 先做服务器配置语法检查，再用临时客户端真正经过新公网入口请求 ISP；不能只测旧本地代理端口。
5. 核错误凭据失败、唯一 ISP 出站；服务端出站约束另设计和测试，不自动搬入陌生防火墙脚本。
6. 在本地生成节点链接/二维码和独立配置文件。二维码可能只加节点，不加 DNS/规则；两者分别核对。禁止在线转换或上传二维码。
7. 用户导入后先做无账号 HTTPS 探测。蜂窝、Wi-Fi 分开测，随后再测锁屏、换网、客户端退出和恢复。
8. 通过后才接入目标应用；热点电脑是另一套测试，不让手机本机结果代替。

## 已知失败为何保留

历史项目曾出现：服务端和电脑经过新加密入口返回正确 ISP，手机导入后却完全断网。该手机结果未验收、原因未定，不能据此交付可直接套用的手机配置。

因此本版本提供架构与适配检查表，**暂不发布手机可一键导入的节点或配置**。这不是让新手自己猜，而是让其 Agent 明确知道还必须完成哪些适配和真实证据。

遇到手机全断网：先按离线卡恢复旧节点/旧配置，保存出错时间与脱敏日志，不同时改 DNS、路由、协议和多个系统开关。不要用真实付款、账号注册或业务上传作首次连通性探针。
