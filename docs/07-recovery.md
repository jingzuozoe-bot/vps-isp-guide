# 先准备离线恢复，再动网络

目的：即使 AI、浏览器、代理一起失联，你仍能恢复电脑。

## 切换前必须保留

- 原客户端名称、配置选择和系统代理/DNS 原值；不要假设原值一定为空。
- 当前能用的独立管理通道，VPS 供应商控制台，必要的本地管理员能力。
- 本次改动清单、备份位置和 [填好的恢复卡](../templates/recovery-card.md)。
- 能离线打开的步骤；不能只放在聊天或需要网络的网页。

## 本库局部 SSH 路线

若只运行前台 SSH，未改任何系统设置：关闭测试应用，Ctrl+C 停指定隧道即可结束。本地 curl 失败不代表整机被断网。

若额外启用了客户端系统代理：先退出受保护应用；在该客户端关闭新系统代理，按记录恢复**原来的**代理值；切回原客户端/原配置；核对原 DNS 与联网。不要在新入口停止后把敏感应用留着尝试直连。

恢复原网络意味着用户明确放弃本次受保护路径；若要求故障时绝不直连，就让受保护应用保持关闭，待新路径恢复并验证后再开。

## 什么时候停止推进

不能说明原值是什么；恢复依赖新客户端仍运行；遇到权限拒绝就要求全盘权限；防火墙规则身份不匹配；唯一联络链路将被测试打断；出现应用打不开或持续锁定。此时不叠加新规则，先恢复本次已记录变更。

## 不要这样“救网”

不全局 flush 防火墙，不重置所有网络服务，不删除整个客户端目录，不锁应用目录，不更改全机权限。恢复命令必须针对清单中的对象；本库不提供未知环境通用恢复脚本。

更严格的防护如果以后实现：紧急撤销必须独立于规则识别、主控制器与在线聊天，并覆盖异常退出、重启遗留、错误配置等场景。先证明撤销可靠，再做会切断通信的测试。
