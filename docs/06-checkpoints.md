# 验收检查点：有证据才通过

目的：明确哪里真的可用，失败时在哪一层停止。状态只能是未测、通过、失败、不适用。

| 编号 | 动作 | 通过依据 | 失败后 |
|---|---|---|---|
| C00 盘点 | 记录设备、版本、资源、原网与依赖 | 能说清原网络和目标范围 | 补缺项，不修改 |
| C01 采购 | 核 SKU、地区、费用、续费、协议 | 本人明确认可订单 | 不付款 |
| C02 回退 | 离线保存原值与恢复步骤 | 用户能独立找到且步骤针对本次变更 | 不切网 |
| C03 VPS→ISP | 从 VPS 显式请求 ISP 代理 | HTTPS 成功且出口匹配订单 | 排上游，不改本地 |
| C04 设备→VPS→ISP | 本地显式代理请求 | 两个独立回显一致，范围注明 | 停候选，原网保留 |
| C05 单应用 | 指定应用真实交互 | 应用接入证据与出口/流量证据相互印证 | 停应用，恢复配置 |
| C06 局部故障 | 停测试隧道后同请求失败 | 有时间戳和错误，恢复后重验 | 不宣称停连 |
| C07 DNS/IPv6/UDP | 每类协议独立测 | 有对应路径或明确阻断证据 | 标失败/未测，不放宽 |
| C08 生命周期 | 客户端退出、上游失效、锁屏、换网、休眠/重启 | 故障窗口持续观察，恢复路径通过 | 停扩展与自动化 |
| C09 手机/热点 | 手机本机与共享电脑分别测 | 各自独立记录 | 不能互相替代 |
| C10 交付 | 保存操作卡、期限和版本 | 用户知道模式、恢复和维护方式 | 补交接 |

C00–C06 通过仍只支持所测普通 TCP/单应用范围。要求系统级故障停连时，C07/C08 不能跳过；本库没有可直接安装的停连实现。普通代理目标下可接受未测边界，但必须向用户写明，不能把未测改为通过。

## 记录每次测试

复制 [证据示例](../examples/checkpoints.example.json)，在仓库外保留：检查点、状态、时间与时区、OS/客户端/核心版本、配置校验摘要、目标范围、实际观察、预期、失败错误、恢复结果和私密证据文件位置。公开只交脱敏结论。

不适用必须有理由，例如“只验 TCP 显式代理，不提供 UDP”，而不是“测不出来所以不适用”。版本、规则或网络环境变了再决定复验，别反复做条件未变的探针。

## 负测试如何不把自己锁死

先关闭可能旁路的业务应用，保留独立联络；先做指定测试端口/请求的局部故障，再考虑系统范围。每次只注入一种故障，定好测试上限与独立恢复。不得为演示全机阻断而直接加载未经恢复验证的规则。

DNS 页面显示公共解析器，不自动说明泄漏：要对比远端解析基线和实际路径。WebRTC 未见公网候选，也不能推断所有 UDP 已被阻断。
