# 验收检查点：有证据才通过

目的：明确哪里真的可用，失败时在哪一层停止。状态只能是未测、通过、失败、不适用。

| 编号 | 动作 | 通过依据 | 失败后 |
|---|---|---|---|
| C00 盘点 | 记录设备、版本、资源、原网与依赖 | 能说清原网络和目标范围 | 补缺项，不修改 |
| C01 采购 | 核 SKU、地区、费用、续费、协议 | 本人明确认可订单 | 不付款 |
| C02 回退 | 离线保存原值与恢复步骤 | 用户能独立找到且步骤针对本次变更 | 不切网 |
| C03 VPS→ISP | 从 VPS 显式请求 ISP 代理 | HTTPS 成功且出口匹配订单 | 排上游，不改本地 |
| C03a 出口名声 | 至少两家独立库核对国家、城市，并查 ASN/网段标记 | 国家与城市匹配，且未见该 ASN/网段被广泛标成住宅代理、匿名 VPN 或代理池 | 向供应商换另一个 ASN，再从 C03 重验 |
| C04 设备→VPS→ISP | 本地显式代理请求 | 两个独立回显一致，范围注明 | 停候选，原网保留 |
| C05 单应用 | 指定应用真实交互 | 应用接入证据与出口/流量证据相互印证 | 停应用，恢复配置 |
| C06 局部故障 | 停测试隧道后同请求失败 | 有时间戳和错误，恢复后重验 | 不宣称停连 |
| C07 DNS/IPv6/UDP | 每类协议独立测 | 有对应路径或明确阻断证据 | 标失败/未测，不放宽 |
| C08 生命周期 | 客户端退出、上游失效、锁屏、换网、休眠/重启 | 故障窗口持续观察，恢复路径通过 | 停扩展与自动化 |
| C09 手机/热点 | 手机本机与共享电脑分别测 | 各自独立记录 | 不能互相替代 |
| C10 交付 | 保存操作卡、期限和版本 | 用户知道模式、恢复和维护方式 | 补交接 |

C03 通过只说明这次 HTTPS 走了订单上的出口。C03a 紧挨在后面做，它未通过就不要把 C04 标成通过。

至少用两家相互独立的地理或属性库核对国家与城市。某家给不出城市，就换一家，不能算进这两家。ASN 和运营商记在仓库外。再看该 ASN 或网段有没有被大量标成住宅代理、匿名 VPN 或代理池。可参考 ping0、ippure、Scamalytics、IP2Location。任何一家的分数都不能单独决定通过或失败。

公开只写匹配、不匹配或有风险标记，不写真实 IP。国家与城市对上写匹配，对不上写不匹配；该 ASN 或网段被大量标成上述用途时，再写有风险标记，检查点失败。两项可以同时写。各家说法冲突时保持未测或标失败，写明冲突在哪一类标记，不取平均分，也不另写“干净”。失败后向供应商申请换到另一个更干净的 ASN，不要只换同一 ASN 里的相邻地址；新地址从 C03 重验。通过只代表这次查过的库。这一步不代替目标服务的账号资格，也不提供规避限制的做法。

C00–C06（含 C03a）通过仍只支持所测普通 TCP/单应用范围。要求系统级故障停连时，C07/C08 不能跳过；本库没有可直接安装的停连实现。普通代理目标下可接受未测边界，但必须向用户写明，不能把未测改为通过。

## 记录每次测试

复制 [证据示例](../examples/checkpoints.example.json)，在仓库外保留：检查点、状态、时间与时区、OS/客户端/核心版本、配置校验摘要、目标范围、实际观察、预期、失败错误、恢复结果和私密证据文件位置。公开只交脱敏结论；C03a 公开只写匹配、不匹配或有风险标记。

不适用必须有理由，例如“只验 TCP 显式代理，不提供 UDP”，而不是“测不出来所以不适用”。版本、规则或网络环境变了再决定复验，别反复做条件未变的探针。

## 负测试如何不把自己锁死

先关闭可能旁路的业务应用，保留独立联络；先做指定测试端口/请求的局部故障，再考虑系统范围。每次只注入一种故障，定好测试上限与独立恢复。不得为演示全机阻断而直接加载未经恢复验证的规则。

DNS 页面显示公共解析器，不自动说明泄漏：要对比远端解析基线和实际路径。WebRTC 未见公网候选，也不能推断所有 UDP 已被阻断。
