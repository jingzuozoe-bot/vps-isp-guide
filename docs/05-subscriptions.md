# 服务订阅、客户端配置、配置订阅是三件事

目的：避免把带密码的节点发进公共仓库或在线转换器。

| 你拿到的东西 | 用处 | 是否公开 |
|---|---|---|
| VPS/ISP 套餐订单 | 付费用资源 | 订单与账号私密 |
| 代理端点 + 认证 | 连接服务 | 当作秘密 |
| YAML/JSON 配置 | 告诉客户端如何连 | 含秘密时私密 |
| 订阅 URL/二维码 | 让客户端下载/导入配置 | 持有者可能拥有访问权 |
| 本库 GitHub 链接 | 让人和 Agent 读教程 | 公开，不含可用节点 |

## 首次优先：本地文件导入

让 Agent 根据官方文档生成单一客户端候选，把占位符在本地受限文件中替换。通过语法检查、出口和恢复检查后导入独立配置。换一个客户端就重新确认协议和字段，不能只改扩展名。

本库 SSH 模式的 127.0.0.1 属于运行隧道的那台电脑。把这份配置导入手机不会连接电脑，手机会去找自己。不得为方便而把电脑 SOCKS 无认证开放到整个局域网。

## 以后需要自动更新订阅时

1. 先明确订阅给谁、在哪些设备使用、谁能读文件。
2. 选择支持认证和 HTTPS 的私有分发方式；核服务端实际鉴权、日志和备份权限。
3. 不把节点放公共 GitHub、公开 Gist、Issue、网页源码或公开构建产物。
4. 随机长链接只是持有即授权的一种凭据；它仍可能进入剪贴板、访问日志、截图和浏览器历史。
5. 不用未知在线转换器。需转换时让 Agent 在本地运行审阅过的工具，输入输出都留本地。
6. 更新前保存上一版；更新后做语法、唯一出站和真实请求核验。订阅更新不应悄悄加 DIRECT 或换成裸 VPS。
7. 凭据泄露先在供应商端轮换/撤销，随后更新设备；删除 Git 提交不能替代轮换。

本版本**不提供公开订阅托管服务，也不提供生产级私有订阅服务器**。本地导入是可用的起点；手机的加密入口须另做平台适配。
